## 二、接入原理（30 秒了解）
我方是"CAS 客户端"，登录动作全部由贵方 CAS + 企业微信完成，我方只在最后一步拿票据换取用户身份：

```
员工浏览器            我方平台                     贵方 cas.51aes.com        企业微信
   │─ 访问受保护页 ─▶│ 检测未登录                     │                        │
   │◀───────── 302 跳转到 CAS /login?service=我方回调地址 ──────▶│ 展示扫码页        │
   │──────────────────────── 员工用企业微信扫码 ───────────────┼───────────────▶│
   │                                                            │◀ 认证通过，发票据 │
   │◀──── 302 回到 我方回调地址?ticket=ST-xxxx ────────────────│                  │
   │─ 我方后端拿 ticket 调 /p3/serviceValidate 验票 ──────────▶│                  │
   │                                                            │◀ 返回 工号/姓名/部门 │
   │◀──── 建立本地会话，进入平台 ────│                          │                  │
```

**关键点**：只有登记在 CAS 服务注册表中的 service 才能发起登录，否则一律被挡回登录页。因此**第 1 项配置是打通的前提**。

**若贵方使用 Apereo CAS**，可参考以下服务注册示例（字段名以贵方目录实际为准）：
```json
{
  "@class": "org.apereo.cas.services.RegexRegisteredService",
  "serviceId": "^https?://(www\\.echoswiki\\.com|49\\.233\\.170\\.127)/auth/cas/callback.*",
  "name": "YuanquSolutionPlatform",
  "id": 100xx,
  "description": "园区解决方案平台（五阶段方案作战台）",
  "evaluationOrder": 100,
  "attributeReleasePolicy": {
    "@class": "org.apereo.cas.services.ReturnAllowedAttributeReleasePolicy",
    "allowedAttributes": [ "java.util.ArrayList",
      [ "employeeNumber", "cn", "deptName", "mail" ]
    ]
  }
}
```
> `serviceId` 用正则同时覆盖生产域名与联调 IP；`allowedAttributes` 里的字段名请替换为贵方目录里的真实属性名（见事项 3）。

### ✅ 事项 2【必做】确认带属性的验票端点已开放

- 首选：`/p3/serviceValidate`（CAS 3.0，返回属性）
- 请确认该端点已开放；若贵方仅开放 `/serviceValidate`（CAS 2.0，**不返回属性**），请告知，我方将改用 `/samlValidate` 或请贵方开启 p3。

## 五、联调与验收流程（拿到配置后，我方半天内可完成）
| 步骤 | 动作 | 预期现象 / 验收标准 |
|------|------|---------------------|
| 1 | 贵方完成事项 1~3（+按需 4/5），并回传属性字段名 | 我方收到字段清单 |
| 2 | 我方开启 SSO 开关，用测试工号访问平台 | 自动跳转到贵方 `/loginPage` 扫码 |
| 3 | 企业微信扫码通过 | 自动回跳我方平台并显示"已登录：姓名/部门" |
| 4 | 我方调用 `/api/me` 校验 | 返回正确的工号/姓名/部门/邮箱 |

> 若步骤 2 未跳转扫码、而是被打回登录页 → 通常是 **service 未登记（事项 1）** 或回调地址与登记的不完全一致。
> 若步骤 3 回跳后拿不到姓名/部门 → 通常是 **未开 p3 端点（事项 2）** 或 **属性未释放（事项 3）**。

## 六、安全与合规说明（供贵方评估）
- 我方**不接触员工密码**，全程由贵方 CAS + 企业微信完成认证，我方仅在最后凭一次性票据换取身份信息。
- 我方仅接收**工号、姓名、部门、邮箱**等基本信息用于展示与归属，**不留存任何凭据/密码**。
- 我方会话使用 **HttpOnly + 签名 Cookie**（防篡改），生产环境启用 **Secure（HTTPS）**，并支持 **CAS 单点登出**。
- 接入采用**功能开关**，可由贵方一声令下随时停用；停用后平台回到无 SSO 状态，不影响贵方系统。
- 回调地址做了**站内跳转校验**，杜绝开放重定向风险。

## 七、常见问题（FAQ）
**Q1：需要贵方开发或改代码吗？**
不需要。贵方只做 CAS 侧配置（登记 service + 释放属性 + 按需放行网络）。

**Q2：会影响现有其它已接入 CAS 的系统吗？**
不会。新增一个 service 条目相互独立，不改动既有配置。

**Q3：我方为什么要 IP 地址联调？不能直接用域名吗？**
我方域名正在备案审核，HTTPS 未生效；备案通过后立即切回域名并请贵方删除临时 IP 项。

**Q4：拿到的用户信息会怎么用、存哪里？**
仅用于平台内显示"当前登录人/部门"与内容归属，存在我方服务器会话中，不外传、不落库敏感字段。

**Q5：如果只想先小范围试点？**
可先在企业微信里把应用可见范围限定到试点人员；我方侧也可仅对部分工号开放。
